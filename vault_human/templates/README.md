# Templates

Empty note skeletons. Three generic ones are included; domains add their own.

| Template | For |
|---|---|
| `dev-log.md` | One work session on one project |
| `quick-capture.md` | Anything, captured fast, sorted later |
| `study-note.md` | Something being learned |

## What makes a template worth having

**Fixed headings, so the gaps are visible.** A dev log with an empty "Problem" section
tells you the session had no problem worth recording. Free-form prose cannot say that.

**Front matter the tooling can read.** Date, project, tags. This is what makes a pile of
notes queryable later.

**Small enough to actually fill in.** A template with twelve sections gets abandoned, and
an abandoned template is worse than none — it makes the notes that do exist look
incomplete by comparison.

## Domain templates

Domains define their own beyond these, and they can be as specific as the work is. A
template is not a document standard; it is a starting point for one kind of note that
recurs often enough to be worth pre-shaping.
